## 1. なぜ変えるか — 差し戻し⑤の構造診断

現行 carry 系は「AI が一枚絵に焼き込んだシートを生成 → 手の位置を実測 →
手前手だけをピクセル判定で切り出して重なりを偽装」という流れで、
**レイヤー情報を捨ててから復元している**。差し戻し 4 ラウンド分の不具合
（持ち物の帯分断・奥腕の前描画・3 本手）はすべてこの復元工程が根で、
持ち物 × 服 × ポーズが増えるほど復元コストと生成ガチャが掛け算で効く。
また 96px の絵ではエージェントの解剖判定（手前/奥の腕）自体が曖昧になる
ことも実測した（PR #110 の差し戻し④⑤）。

## 2. 確定アーキテクチャ（三層）

役割を 1 層 1 権威に分ける。いずれも本リポジトリで実測済みの部品の
組み合わせで、新規発明はない。

| 層 | 権威 | 実体 | ガチャ |
| --- | --- | --- | --- |
| 第 1 層: 3D 正本 | キャラの同一性・ポーズ | キャラごとのリグ済み GLB（Meshy）を台帳管理。モーションはカタログ（680 種）＋リターゲットで全キャラ使い回し | なし（決定論。ただしリターゲットのループ品質はキャラごとガチャ — girl gangnam の実測 — なので登録時に骨署名閉包の機械ゲートで検収） |
| 第 2 層: 動画清書 | 画風 | 3D レンダー緑参照 → wan replace / seedance crosschar（現行レーン）。[Wan-Animate-2](https://github.com/Wan-Video/Wan-Animate-2) が差し替え候補 | **ここだけ**（テイクガチャ。機械ゲート＋videoReview＋オーナー目視で検収） |
| 第 3 層: レイヤー出荷 | 重なり順 | 「腕なし素体＋手前腕＋奥腕」に分離して出荷し、ランタイムで 奥腕→アイテム→手前腕 と合成。アイテム＝PNG＋grip 点 | なし（3D 腕マスクで機械切り出し — §2.1） |

裏付けの実測（DP-B スレッド）: 3D モーション参照で歩行の脚交互・腕逆相が
**構造的に**成立（videoReview「現行本番 walk より上」）、replace は承認
テイクの動き・様式を完全継承、ハイブリッドは「production-ready」検収。

### 2.1 第 3 層の鍵 — 3D 腕マスク

腕がどのピクセルにあるかは第 1 層（3D）で既知。GLB の腕ボーン/頂点
グループだけを可視化した「腕マスク」を参照動画と同カメラでレンダーし、
清書コマに重ねて腕層を機械的に切り出す（Wan-Animate は骨格信号で空間
整合するため位置ズレが小さい — マスクは dilate＋局所マッティングで吸収）。
差し戻し⑤で苦しんだ肌色ヒューリスティック・ピクセル考古学を全廃する。
補助手段はモデルベースのレイヤー分解
（[See-through](https://github.com/dhjeon-ai/see-through) — 一枚絵を遮蔽
補完つきで最大 23 意味レイヤーに分解、OSS）。設計思想は ①d の
R3（headless 体セル＋頭グループ — [docs/avatar-head-group.md](./avatar-head-group.md)）
の腕版。

## 3. オーナー 3 条件への適合

**組合せ爆発なし**（すべて足し算 or 小さな線形）:

| 資産 | 増え方 |
| --- | --- |
| アイテム追加 | PNG 1 枚＋grip 点のみ。シート再生成ゼロ（アイテム×服の掛け算が消える） |
| 服追加 | 腕なし素体シート 1＋腕ペア（袖が服に依存するため 服数 × carry ポーズ数。carry ポーズは heavy/light の 2 で小さな線形係数） |
| モーション追加 | カタログ選定＋リターゲット（全キャラ・全服で使い回し） |
| キャラ追加 | A ポーズ原画 1 枚＋GLB 化 1 回（~43cr ≈ 130 円）＋動作ごと清書 |

**2D/3D ゲーム転用**: ポーズフレーム出荷はそのまま 2D ゲームのスプライト
（MapleStory 本家と同構造）。新モーションはカタログから量産。**3D ゲームは
第 1 層の GLB がそのまま資産**になる — 単独案（案 1〜3）のどれも提供
できない性質で、三層構成を選ぶ決め手（VISION 決定ログ 2026-08-11 の
「3D は必要になってから」と整合: GLB は工場の副産物として自然に貯まる）。

**品質**: ガチャは第 2 層の 1 箇所に隔離され、重なり順は構造的に正しく、
検収ゲート（機械 lint・videoReview・オーナー目視 — asset-factory 運転
知見 14）は不変。

## 4. 質疑の記録（2026-08-14 オーナー質疑への回答）

差し戻し⑤の締めでエージェントが提示した 3 案への質疑と結論:

- **案 1（腕をレイヤーとして持つ）**: 過去に棄却された方式では**ない**。
  棄却済みの v1「自前パーツ回転リグ」（目測組み立てが律速・棒の手足 —
  avatar-rig.md §1）とも、差し戻し⑤まで使っていた「後付け切り出し」とも
  別物（案 1 は回転も変形もせず、工場でレイヤーを分離して出荷するだけ）。
  組合せ爆発もしない（§3）。→ **三層の第 3 層として採用**
- **案 2（持ち物ごと動画に焼き込む）**: item×outfit で爆発する。
  → **オーナー裁定で最終手段（保険）**。頑固なアイテムの個別対応にのみ使う
- **案 3（Spine/スケルタル）**: Spine 本体のスパイクは未実施（DP-A の
  移行先として保留のまま）。過去の棄却（v1 回転リグ・DP-B Blender ベイク
  「紙人形」）は変形ベースの実装への判定で、Spine でも変形の見た目
  リスクとキャラごとリグ較正コストは残る。3D ゲームには寄与しない。
  組合せ爆発はしない（スケルタルの本領）。→ **保留を維持**。実施
  トリガー: 2D ゲームでランタイム補間・大量モーションが必要になった
  とき。第 3 層のパーツ分離資産がそのまま前提資産になるため先行投資は
  無駄にならない
- **解像度方針の確定**: 動画生成は **720p**（fal replace は 720p が上限で
  1080p が存在しない。seedance の課金はピクセル比例で 720p→1080p は
  約 2.25 倍/テイク、出荷 192px への LANCZOS 縮小で追加ディテールは
  消える — 同予算ならテイク数に回す方が歩留まりに効く）。静止画
  （A ポーズ・アイテム・服替え編集）は **1080p 以上**（枚単価課金で
  コスト増なし・検品精度に直結）。出荷は **4x = 192px**（表示は論理
  48px、画面実寸は ~63px@1080p 窓〜~190px@Retina なので 4x 超は画面に
  現れない。4x の恩恵は Retina・将来ズーム・検品/機械ゲート精度）
- **将来ゲームへの適合**: 案 1 = ○（本家構造そのまま）/案 2 = ✕（爆発）/
  案 3 = ◎（ゲーム標準・ただし 2D のみ）。三層構成は 2D・3D 両対応
