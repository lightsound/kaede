### fal replace レーン（マスターテイク方式）

**発注書だけでキャラ×動作が増える**: 振り付け×シルエット系統ごとの承認済み
マスターテイク 1 本（`register` が緑背景・承認出所・ループ閉包を機械確認して
トリム版を R2 登録）に対し、新キャラは identity 画像 1 枚の発注書で
`produce` を呼ぶだけ。動き・タイミング・シルエット枠はマスターから完全
継承される（枠が合わないマスターは髪ボリュームが潰れる — PR #101 実測）。

```sh
export CLOUDFLARE_API_TOKEN=...
python3 scripts/factory/replace_lane.py produce order.json --budget 0.5
python3 scripts/factory/replace_lane.py costs   # fal 残高照合（BYOK はログ cost=0）
```

発注書は `{id, motion, family, identity, standSource, resolution?, useTurbo?,
cells?}`（identity / standSource は R2 sha256 かローカルパス）。produce は
台帳照合 → マスター取得（sha256 照合）→ identity 正方形化 → replace 投入
（state 永続化・--budget 停止・キー再利用ガード）→ 緑服セーフキー →
ループ検証 → **瞬き回避セル選定**（位相等価コマから眼開度最良を選ぶ）→
透過背景シート＋neckAnchors → 検品材料（マスター並列モンタージュ・96px
ループ動画・顔ストリップ）まで一気通貫。レシピは wan replace 480p・
steps 既定 20（ノブ非公開 — オーナー裁定）・品質を上げたいテイクのみ
`useTurbo`（約 3 倍遅・追加費用なし）。

### walk レーン（歩行統一 — 2026-08-12・①d 論点 6 の裁定）

**全シートの walk セルは登録済み歩行マスター 1 本から出る**（boy 系 =
`walk/boy`・girl 系 = `walk/girl`・carry 系 = `walk-carry/boy`。マスター自体は
Meshy プリセットモーションの 3D 緑参照 × seedance 清書 — 金型は新モーション
鋳造時に 1 回だけ）。旧方式（wan-2.7-i2v にプロンプトで歩行を演技させる）は
本番から全廃。

```sh
python3 scripts/factory/walk_lane.py produce <order.json> --master walk/boy --mode extract
python3 scripts/factory/run_avatar.py <order.json> --from-stage import   # 標準取り込み＋全ゲート
```

- `extract`: シートのキャラ = マスターのキャラなら**モデル呼び出しゼロ**で
  マスターからコマを直切り出し（danceMaster 前例・運転知見 19）。
- `replace`: 他 identity への転写（fal wan-2.2 animate/replace —
  シルエット系統の合うマスターを選ぶ・運転知見 18）。
- 選定は cycle_scan（台帳の機械既知周期・頭スキップなし・**台帳
  loop.start より前の ease-in 区間は走査しない** — girl の逆位相ボブは
  ループ外セル 3/9/15/21 が源流だった、差し戻し② 2026-08-13）＋ walk
  ゲート一式（頭部整合・ドリフト・leg phase＝IoU 一本・**首接合部**・
  **ボブ位相**）。アンカーは足スプレッド最大＝近側接地（3/4 視点で唯一
  信頼できる脚位相観測量 — 符号付き足シグナルはレンダーごとに反転し、
  遠側接地は奥行き相殺で通過並みに細く写る）＋丸め四分位
  （foot_phase.stride_quad）。合成は component erase ＋ alpha_composite
  （girl 首切れ 3 ラウンドの根治規則）で、頭はシートの committed stand
  セルから貼り直す — 動画側の髪は最終シートに残らない。
- **首ボブは処方制**（差し戻し② 2026-08-13 — 増幅制（ゲイン 4）を全廃）:
  合成後の首高さを「接地セル = stand −1.5%・通過セル = stand +1.5%」に
  **処方**する（compose_sheet の BOB_AMPLITUDE_FRAC ≈ p-p 3px @96px =
  オーナー承認済みの旧 boy パターン）。マスター実測ボブの増幅は、チビ
  寸法では実測偏差（±1px 前後）がノイズ支配のため**シートごとにランダムな
  位相のボブ**を作る — girl の逆位相・carry の 7px バウンスの正体。
  **水平の頭ずらしは引き続き封印**（チビ頭がセル bbox 両端を規定 →
  中心揃え＋下辺中央アンカーで全体平行移動に化け、顔は動かず足が滑る —
  実測済み）。
- **マスターの視点は正準右 3/4 で鋳造する**（差し戻し対応 2026-08-12）:
  replace/extract はマスターのシルエットを継承するため、緑参照が profile
  だと最終セルまで真横になる（v1 carry の棄却理由 — 後傾・脚細・シャツ
  欠けの主因）。Meshy GLB は `spike_tripo_render.py` の yaw45 で自前
  レンダーしてから seedance 清書。
- **carry は持ち物の重量で 2 系統**（オーナー裁定 2026-08-12）:
  `walk-carry/boy`（両手を腹前で揃える — **Texting_Walk_inplace 金型**。
  差し戻し③ 2026-08-13: Carry_Heavy_Object 系は空手にすると腕が
  「夢遊病」に見えると棄却。両手前保持の直立自然歩行はカタログ 680 本
  中 Texting_Walk がほぼ唯一）と `walk-carry-light/boy`（片手掌を体の
  前に静止保持 — Walking_with_Phone_inplace 金型の右腕を fcurve 展開:
  前腕 X−80°+上腕 X+30°/Y+25°。素の phone ポーズは拳が胸に密着し、
  合成アイテムが胴へ沈んで読めない）。item manifest の
  `carryStyle`（light/heavy）でクライアント・試着ステージがシートを
  選ぶ（light 未生産の服は heavy へフォールバック）。carry の
  handAnchors は**シートごと・フレーム別に描かれた手の上を実測**
  （heavy = 揃えた両手のトップ・light = 差し出した掌のトップ。皮膚
  近接 lint が検証。計測バンドが顎の肌・スイング側の手を掴む誤検出に
  注意 — 実測 2026-08-13）、hand.png は order の `handLayerFrom`
  （既定 stand）で **walk-a の手から切り出し**、`handLayerSide: near`
  で**手前側の手だけ**を残す — 両手ブロブ全体を前面に貼ると持ち物が
  肌色の帯で分断される（差し戻し③: 正しい重なりは手前の手→アイテム→
  奥の腕。奥の手は体セル側に残して持ち物の後ろに置く）。stand の
  腰ミトンを別ポーズの手の上に貼ると第二の手が浮いて見える（差し戻し②
  2026-08-13）。**保持腕は seedance が自然歩行へ引き戻す**: 参照で
  静止していても「stays PERFECTLY STILL」を明示しないと軽いスイングに
  化ける（v1 wan 時代の実証文言の再確認 2026-08-13）。**片手静止掌の
  鋳造はガチャが強く未確立**（腰前掌 3 テイクとも胸で拳化/様式ドリフト/
  掌ふらつき — 2026-08-13）: light 系統は当面 v4 texting（両手）から
  抽出し、light 変種シートは heavy 変種の**バイトコピー**（同一
  マスター・同一セルなので choreography も服も一致 — nano 再編集の
  レイアウト増殖ガチャからも離脱）。**nano は服替え編集で腕を再解釈
  する**（両手揃えの boy シート → 変種は「片手を胸・片手前」に 3/3
  ロールとも化けた。IoU 0.86-0.97 はこれを許容する）— 変種の
  handAnchors は必ずシート実測（per-sheet 規則の再確認）。
- 服替え変種（red/pants ± carry ± carry-light）は素体の新 walk シートへの
  **シート編集**が実測で優位（$0.10/着・IoU ゲート・変種間で振り付けが
  バイト一致に揃う）。replace の identity 差し替え（$0.155〜/着）は系統の
  合うマスターが無い新シルエット向け。フードなど**首ピンチ検出を壊す服は
  `lint.neckFrom`** でペア素体 manifest から首を転写検証する（構築不変量
  — 編集レーンの IoU ゲートが構築保持を証明）。旧 carry の staticize
  （上半身の内部色移植）は v2 マスターで腕が自然に動くため**撤去**
  （order の `staticUpperBody` で opt-in のみ — 顔 RGB の移植が二重顔の
  原因だった）。

## アート lint（①b(a)⑵ の穴への構造対応 ＋ PR #94 棄却で較正した 2 検査）

1. **neck**: 色（肌ブロブ）ではなく、シルエット幅プロファイルの
   「頭ピーク → くびれ → 胴ピーク」構造で検出。フード等で最細行ヒューリスティック
   が腰へ落ちる失敗を機械で弾く
2. **hand**: carry は腰バンド内のシルエット最大幅行の中心（ミトンパッド）。
   股下ストライドの幅ピークには乗らないようバンドを `[0.55h, 0.70h]` に制限。
   swing は発注書オーバーライド優先。shirtless の `handLayer` 切り出しは
   胴まで洪水しないよう、大きすぎる塗りつぶしを楕円キャップで打ち切る
3. **パレットコントラスト**（opt-in `lint.contrastBase`）: ベース服の主要色との
   最小距離が閾値未満なら不合格（白いアイテムが白シャツに溶ける実測への対応）
4. **頭部整合性**（新設）: 各コマの首行位置・上首部の最大幅／画素量を stand と
   比較（Δ≤3px・幅比≤1.05・画素比 0.90〜1.05 — 出荷 4 シートと PR #94 棄却品で
   較正）。二重頭（画素比 1.61）とボブ毛のはみ残り（1.07〜1.08）を機械で弾く
5. **コマ間パレットドリフト**（新設）: 各コマの**内部**有意色（境界の
   アンチエイリアス混色は除外 — 黒髪×淡色キャラで誤検出 98〜100% を実測）が
   stand パレットから距離 45 超なら不合格。wan がキャミを灰化した実ドリフト
   （57〜58）を 2 テイクで検出。同系色内の微妙な肢体トーン差（PR #94 のピンク
   肢 ≤29）は閾値では分離できず**視覚ゲートの領分**
6. **シルエット IoU**（編集レーンのみ）: 各ポーズの編集結果 vs 編集元コマの
   IoU ≥ 0.80（服替え実測 0.85〜0.97。ポーズ崩壊は contact コマが大きく落ちる）
7. **ペア素体色一致**（opt-in `lint.matchStand`）: carry 変種の stand を
   ペア素体の stand とドリフト比較。試着ステージは持ち物クリックで
   素体⇄carry を切り替えるため、肌トーンの跳びは可視欠陥（リテイクが
   白肌で返った実測から追加）
8. **首接合部**（新設 2026-08-12 — ①d 論点 6 の girl 首切れ再現）: walk 各
   コマの neck アンカー窓 ±5px・アンカー行 −4〜+2 の帯で、行ごとの実効
   アルファ幅 ≥3.0px（棄却済み girl walk-c は 2.0 = 文字どおりの頭体断絶）
   ＋最悪行の soft/solid 比 ≤1.5（半透明ブリッジ — 自己マスク paste の
   α二乗劣化も端から検出）。旧 girl セル=陽性・committed 健常セル=陰性で
   較正。stand は免除（接合部フリッカーは再生速度の歩行アーティファクト）
9. **leg phase**（2026-08-12 に IoU 一本へ再較正）: walk-a vs walk-c の
   シルエット IoU ≤ 0.90（ほぼ同一ポーズ = ストライド消失の検出）。旧
   足位置符号検査は基準系（stand 相対 vs サイクル相対）でレンダーごとに
   反転し不安定と実測 — 撤去
10. **ボブ位相**（新設 2026-08-13 — 差し戻し②の NG1/NG2 を機械化）: walk
    4 セルの首高さ（フレーム高 − 首行）が「接地 walk-a/c ≤ 通過 walk-b/d
    −1px」の 2 山パターンで、振幅 p-p が [2,5]px @96px。girl の逆位相
    （47/44/45/48）・carry の過剰（45/51/44/51）・却下された修正 2 案
    （PR #108: 46/46/44/49・PR #109: 44/48/47/44）を全て弾く較正を
    テストに固定。処方ボブ以前の committed シートも再取り込み時に落ちる
    — 免除でなく walk レーンの再走が正
11. **手アンカーの皮膚近接**（新設 2026-08-13 — 「指先・空中アンカー」の
    機械化）: carry シートの hand アンカー ±3px に肌色画素が必須。v2 の
    腕先端アンカー（アイテムが顔の横に浮く）の再発防止。検出でなく記録値の
    検証（lint.neckFrom と同じ位置づけ）

## 運転知見（2026-08-09 通し運転）

1. **nano-banana-2 は「下着・裸」系の語で拒否風 500**（`Failed to parse
   model output`・課金ゼロ）を返しやすい。「dress-up BASE BODY sprite /
   like a swimmer / underwear shorts」の言い回しで一発通過。ジェネレータは
   5xx を 3 回まで自動リトライ（失敗は無課金）
2. **wan の倍周期**: 自己相関の argmax は 2 ストライド周期を掴むことがある
   （実測 12 コマ周期のクリップで 24 を選び、pass スロットに contact が
   落ちた）。基本周期選好（ベスト比 0.9 以内の最小ラグ）で解消
3. **wan は淡い肌・パステル服を再塗装する**（女の子で 3 テイク実測:
   キャミ灰化×2・肢体の黄/ピンク化×1）。`avatar-walk-i2v-locked`
   テンプレ＋発注書 `vars.colorNotes` で服・肌・靴の色を明示固定すると合格
4. **前方に振った腕が首の谷を塞ぐ**コマは構造 neck が誤検出する —
   compose の接地相対 neck 検査で棄却し、±1〜2 コマの近傍候補へ
   自動フォールバック（動画の取り直し不要）
5. **腕の前後交代（交差）は視覚ゲート項目**（オーナー棄却 2026-08-09 —
   「ずっと同じ手が前」）。96px のシルエットでは腕が胴に重なり機械判定
   できない（重心・突出の両信号で分離不能を実測）。プロンプト側は
   `avatar-walk-i2v-arms`（**毎歩入れ替わる**を明示・肘は脱力・モーション

6. **クリーン周期はクリップのどこかにあればよい**: 自動選定した 1 周期が
   ドリフトで落ちても、全ストライド走査＋位相等価置換（cycle_scan.py）が
   同じクリップ内から救済する（girl の採用テイクは走査救済 — 取り直し
   0 本）。**位相を保存しない**近傍置換は周期の等間隔を壊し逆走
   （ムーンウォーク）に見える — 置換は必ず ±k×周期を先に試す。
   置換は**落ちたスロット自身から正確に ±k×周期**で取ること: 別ストライドの
   同スロット値を人手で流用した ~1 コマの位相ずれが「walk-a ≈ walk-d・
   中間地点なし」に見えた（オーナー指摘 2026-08-09 ラウンド 2。
   cycle_scan.py の自動置換はこの規則を守るため再発しない）

   左右反転してストロボになる（videoReview 棄却 2026-08-09）。頭部は
