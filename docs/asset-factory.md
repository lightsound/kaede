## レーンは 2 本（発注書の `template` で自動選択）

| レーン | 用途 | 生成 | コスト実測 |
| --- | --- | --- | --- |
| **動画レーン**（`avatar-stand`） | 新キャラ | nano-banana-2 立ちコマ → wan-2.7-i2v 歩行動画 → 足位置解析 → 頭部合成 | $0.60/本（色ドリフトの取り直しで×1〜3） |
| **シート編集レーン**（`avatar-outfit-edit`） | 服替え・素体変種 | 既存の構成済みシートへの keep-everything 編集（`editSource`）。動画不要・ポーズは構造的に保存 | $0.10/着 |

## 工程

| # | 工程 | 実装 |
| --- | --- | --- |
| 1 | 発注書 | `game.package/<dir>/order.json`。`template` + `vars` で種別テンプレを展開（直書き `prompt` も可）。展開結果は `prompt` に記録（再現性） |
| 2a | 立ちコマ生成 | `google/nano-banana-2` ＋ 基準リファレンス（`canonical/`） |
| 2b | 歩行動画 | `alibaba/wan-2.7-i2v`（誇張スイング。carry は腕固定、淡色キャラは `avatar-walk-i2v-locked` で色固定 — 下の運転知見③） |
| 2c | コマ位相選定 | `scripts/factory/cycle_scan.py` — 足位置重心の自己相関（基本周期選好、`foot_phase.py`）で全ストライドを候補化し、**頭部・ドリフト検査に落ちたコマは位相等価コマ（±k×周期）で置換**して最初のクリーン周期を選ぶ。`--contact` で起点固定（視覚ゲートの裁量） |
| 2d | 頭部合成 | stand の頭部を各 walk コマの構造 neck へ **erase-then-paste**（動画側頭部を消してから貼る — PR #94 の二重頭の再発防止）。neck の接地相対位置が stand とずれたコマは候補フォールバック → 尽きたら fail loud |
| 2e | シート組立 | 5 コマ横一列のグリーンバックシート → `sheet-original.png` |
| 3 | 取り込み | `scripts/import-avatar-sheet.py`（R2 原本解決込み） |
| 4 | アート lint | 構造アンカー乖離・寸法・残渣・頭部整合性・コマ間パレットドリフト・（opt-in）ベース服コントラスト / ペア素体色一致。編集レーンは加えてシルエット IoU |
| 5 | アトラス化 | AssetPack（`pnpm --filter @kaede/client assets:pack`）— ビルド派生物。正は個別 PNG |
| 6 | 原本アップロード | `scripts/upload-asset-originals.py` → R2 `kaede-asset-originals` |
| 7 | PR | 取り込み結果 PNG が見える PR（run_avatar が検品モンタージュも出力）→ オーナー目視 |

運転の入口:

```sh
export CLOUDFLARE_ACCOUNT_ID=... CLOUDFLARE_API_TOKEN=...
python3 scripts/factory/run_avatar.py packages/client/src/game.package/<dir>/order.json --record-yield
python3 scripts/upload-asset-originals.py packages/client/src/game.package/<dir>/order.json
pnpm --filter @kaede/client assets:pack   # 任意・アトラス派生物の確認
```

歩留まり・コスト・所要時間は各通し運転のたびに
[factory-yield.md](./factory-yield.md) へ追記する（DP-B の判定材料）。

## アート lint（①b(a)⑵ の穴への構造対応 ＋ PR #94 棄却で較正した 2 検査）

1. **neck**: 色（肌ブロブ）ではなく、シルエット幅プロファイルの
   「頭ピーク → くびれ → 胴ピーク」構造で検出。フード等で最細行ヒューリスティック
   が腰へ落ちる失敗を機械で弾く
2. **hand**: carry は腰バンド内のシルエット最大幅行の中心（ミトンパッド）。
   股下ストライドの幅ピークには乗らないようバンドを `[0.55h, 0.70h]` に制限。
   swing は発注書オーバーライド優先。shirtless の `handLayer` 切り出しは
   胴まで洪水しないよう、大きすぎる塗りつぶしを楕円キャップで打ち切る
3. **パレットコントラスト**（opt-in `lint.contrastBase`）: ベース服の主要色との
   最小距離が閾値未満なら不合格（白いアイテムが白シャツに溶ける実測への対応）
4. **頭部整合性**（新設）: 各コマの首行位置・上首部の最大幅／画素量を stand と
   比較（Δ≤3px・幅比≤1.05・画素比 0.90〜1.05 — 出荷 4 シートと PR #94 棄却品で
   較正）。二重頭（画素比 1.61）とボブ毛のはみ残り（1.07〜1.08）を機械で弾く
5. **コマ間パレットドリフト**（新設）: 各コマの**内部**有意色（境界の
   アンチエイリアス混色は除外 — 黒髪×淡色キャラで誤検出 98〜100% を実測）が
   stand パレットから距離 45 超なら不合格。wan がキャミを灰化した実ドリフト
   （57〜58）を 2 テイクで検出。同系色内の微妙な肢体トーン差（PR #94 のピンク
   肢 ≤29）は閾値では分離できず**視覚ゲートの領分**
6. **シルエット IoU**（編集レーンのみ）: 各ポーズの編集結果 vs 編集元コマの
   IoU ≥ 0.80（服替え実測 0.85〜0.97。ポーズ崩壊は contact コマが大きく落ちる）
7. **ペア素体色一致**（opt-in `lint.matchStand`）: carry 変種の stand を
   ペア素体の stand とドリフト比較。試着ステージは持ち物クリックで
   素体⇄carry を切り替えるため、肌トーンの跳びは可視欠陥（リテイクが
   白肌で返った実測から追加）

## 運転知見（2026-08-09 通し運転）

1. **nano-banana-2 は「下着・裸」系の語で拒否風 500**（`Failed to parse
   model output`・課金ゼロ）を返しやすい。「dress-up BASE BODY sprite /
   like a swimmer / underwear shorts」の言い回しで一発通過。ジェネレータは
   5xx を 3 回まで自動リトライ（失敗は無課金）
2. **wan の倍周期**: 自己相関の argmax は 2 ストライド周期を掴むことがある
   （実測 12 コマ周期のクリップで 24 を選び、pass スロットに contact が
   落ちた）。基本周期選好（ベスト比 0.9 以内の最小ラグ）で解消
3. **wan は淡い肌・パステル服を再塗装する**（女の子で 3 テイク実測:
   キャミ灰化×2・肢体の黄/ピンク化×1）。`avatar-walk-i2v-locked`
   テンプレ＋発注書 `vars.colorNotes` で服・肌・靴の色を明示固定すると合格
4. **前方に振った腕が首の谷を塞ぐ**コマは構造 neck が誤検出する —
   compose の接地相対 neck 検査で棄却し、±1〜2 コマの近傍候補へ
   自動フォールバック（動画の取り直し不要）
5. **腕の前後交代（交差）は視覚ゲート項目**（オーナー棄却 2026-08-09 —
   「ずっと同じ手が前」）。96px のシルエットでは腕が胴に重なり機械判定
   できない（重心・突出の両信号で分離不能を実測）。プロンプト側は
   `avatar-walk-i2v-arms`（**毎歩入れ替わる**を明示・肘は脱力・モーション
   ブラー禁止）が有効 — 汎用プロンプトの「大きく振る」だけでは wan は
   同じ腕を前に置き続ける
6. **クリーン周期はクリップのどこかにあればよい**: 自動選定した 1 周期が
   ドリフトで落ちても、全ストライド走査＋位相等価置換（cycle_scan.py）が
   同じクリップ内から救済する（girl の採用テイクは走査救済 — 取り直し
   0 本）。**位相を保存しない**近傍置換は周期の等間隔を壊し逆走
   （ムーンウォーク）に見える — 置換は必ず ±k×周期を先に試す。
   置換は**落ちたスロット自身から正確に ±k×周期**で取ること: 別ストライドの
   同スロット値を人手で流用した ~1 コマの位相ずれが「walk-a ≈ walk-d・
   中間地点なし」に見えた（オーナー指摘 2026-08-09 ラウンド 2。
   cycle_scan.py の自動置換はこの規則を守るため再発しない）
7. **ミラー合成（接地＋通過を左右反転して逆相を作る）は不採用**:
   位相・色は完璧だが、3/4 ビューの照明とキャミストラップが半周期ごとに
   左右反転してストロボになる（videoReview 棄却 2026-08-09）。頭部は
   合成で無事でも体の描き込みが向きを持つ
8. **carry シートは取り込み前に静止上半身の内部色移植**
   （`staticize_carry_sheet` — 脚の開始行より上で、walk セルの不透明画素へ
   stand の RGB を転写。輪郭・アルファは各セル維持なので継ぎ目なし）。
   シート一括編集はセルごとに腹部陰影を微妙に描き分け、再生時に
   フリッカーする（オーナー棄却 2026-08-09）— 「腕・胴は静止」という
   carry 仕様を文字通りピクセルで強制する（頭部合成の規則の拡張）。
   丸ごと差し替え案はシルエット差（最大 18%/行）が継ぎ目の段差になるため
   内部色のみ
9. **脚位相ゲートは stand 相対で測る**（girl やり直しラウンド 2026-08-09）:
   足バンド重心の生信号はキャラ固有のオフセットを持つ（girl は対称な直立
   stand でも +2.2、boy は +0.4）。接地 2 コマは stand 相対の信号が
   **逆符号かつ |sig|≥1.2**（承認済み swing シート実測 a'−2.2〜−2.6 /
   c'+2.4〜+2.7）。carry シートは穏やかなストライドのため除外
10. **全ペアの複製上限**: walk 4 コマのどのペアも IoU ≤ 0.90（承認済みの
    最大は (b,d)=0.87）。「同じ脚の接地 2 回」（IoU 0.97 実測）や置換の
    取り違え（(b,c)=0.95）を機械で弾く — オーナーの「片足スキップ・
    中間がない」棄却 2 回をコード化したもの
11. **位相等価置換は隣接ストライド（±1 周期）のみ**: 離れた領域のコマは
    画素ゲートを通ってもレンダリングスタイルが違う（ピンク脚を実測）
12. **静止画モデルによる歩行コマの生成・リスキンは不採用を再々確認**:
    boy シートの全シート/コマ単位 nano リスキンはどちらも脚ポーズを
    軟化・収束させる（①a の「逆足を描き分けられない」の同型）。新キャラの
    歩行は動画レーン一択
13. **動画モデルの選択知見**（girl 実測）: wan はパステル淡色キャラで
    色再塗装が頻発（`avatar-walk-i2v-arms-soft` が脚交代の最良オッズ）。
    seedance-2.0 は色保持が強い一方、i2v は「その場行進」化しやすく、
    **色の置換**（青キャミ→クリーム — 距離ベースのドリフト検査を回避する）
    も起こす。r2v（reference_video モーション転写）は参照が Web URL 必須・
    ≥409,600 画素で、周期内の第 2 接地が痩せる実測 — どのモデルでも
    最終権威はゲート一式＋目視
14. **96px の歩行良否はレビュー AI も不安定**（IoU 0.62 の別ポーズ対を
    「同一」と判定する等、計測と矛盾した判定を複数回実測）。機械ゲート
    （較正済み）で絞り、**最終判定はオーナー目視** — レビュー AI の
    verdict を単独のゲートにしない
