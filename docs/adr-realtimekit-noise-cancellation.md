# ADR: RealtimeKit のノイズキャンセリングをデフォルト ON で導入する

- **ステータス**: **採用（2026-11-27 確定）** — レビュー指摘（判断記録は
  コードコメントではなく ADR に置く）を受けて本 ADR に記録
- **対象**: kaede の通話（packages/client の RealtimeKit ノイズキャンセリング）
- **最終更新**: 2026-11-27

---

## 1. 決定

**ベンダー専用パッケージ `@cloudflare/realtimekit-noise-cancellation`
0.1.1 を採用し、参加直後にデフォルト ON で武装（arm）する。**

通話の音声品質は参加者の環境音に左右される。RealtimeKit 本体には
ノイズ除去が無く、ベンダーが別パッケージとして提供しているため、
それを call.package の内側に閉じ込めて導入する（ベンダー継ぎ目の
封じ込め方針は従来どおり）。

---

## 2. 仕組み

- 実装は `packages/client/src/call.package/realtimekit.ts` の
  `initNoiseCancellation`。`dialMeeting` が join の直後に
  `RealtimeKitNoiseCancellation.init({ meeting, autoManage: true })`
  を呼び、結果を `DialResult.noiseCancellation` として返す。
- `autoManage` の意味: マイクがライブになった時点で処理を有効化し、
  ミュート／ミュート解除や再接続をまたいで維持し、退室時に自身を
  破棄する。kaede 側でライフサイクルを管理しない。
- モデルと worklet のアセットは、有効化時にプロバイダの CDN から
  実行時ロードする。バンドルもセルフホストもしない。

---

## 3. 初期化はベストエフォート

ノイズ除去は通話の付加機能であり、参加そのものを失敗させてはならない。

- 初期化が失敗したら（AudioWorklet の無い環境、アセット CDN に
  届かない等）`initNoiseCancellation` は `undefined` を返し、
  通話は処理なしで続行する。
- パッケージ自体も実行時エラーで自己無効化する設計であり、その場合も
  通話は継続する。
- 初期化できなかった場合はトグル自体を表示しない（→ §4）。
  動かない操作部品を残して説明を強いる形にしない。

---

## 4. トグルの置き場所と表示規約

- UI Kit にはベンダーの別パッケージ向けの表示面が無いため、録画
  トグルと同じ流儀で kaede 独自のボタンを作り、録画トグルの隣に
  置く（`InCallPanel` の `NoiseCancellationToggle`）。
- デフォルトは ON。トグルは「処理の聞こえ方が自分には合わない」
  参加者のための出口である。
- マイクが OFF の間はトグルを無効化する。表示は意図（ON/OFF）を
  保ち、操作だけを止める（理由と設計は §5）。
- ラベルはクリックが実行する動作を名指す（録画トグルの規約と同じ）。
  有効化／無効化はプロバイダの音声ミドルウェアを往復するため待ちが
  見える長さになり、処理中は遷移中の表示でボタンを無効化する。
  この表示ロジックは純粋関数 `noiseCancellationFace`
  （`noiseCancellation.ts`）に切り出し、単体テストで固定する。
  パネルコンポーネント自体は DOM と WebRTC を要するため、
  InCallPanel の他の部分と同様にテスト対象外とする。

---

## 5. 状態同期の設計と残る制約

表示は実状態ではなく、利用者の意図（`wanted`、初期値 ON）を正と
する。理由は、canceller の `enabled` が「処理セッションが存在
するか」を表すためである。

- セッションはマイクがライブな間にしか開始できない（パッケージは
  マイク未使用時の有効化を例外で拒否する）。kaede はマイク OFF で
  参加するため、autoManage で武装していても参加直後の `enabled`
  は false であり、実状態を表示の正に使うと「OFF に見えるが実は
  武装中」という誤った顔になる。
- さらに、マイク OFF のまま `enable()` を呼ぶと、パッケージは
  例外を投げる前に内部の自動有効化フラグ（autoEnablePending）を
  下ろしてしまう。クリック1回で、その通話の間ずっとデフォルト
  ON が静かに解除される。意図を表示の正とし、マイク OFF の間は
  トグル自体を無効化することで、この経路を構造的に塞ぐ。

同期の経路は次のとおり。

- クリックは意図を反転させ、マイクがライブな場合にだけ
  `enable()` / `disable()` を呼ぶ。呼ぶかどうかと向きの判断は
  純粋関数 `noiseCancellationAction` に切り出し、単体テストで
  固定する。
- `audioUpdate` のたびにマイクのライブ状態を読み直し、意図と
  実状態がずれていれば `enable()` を await して収束させる。
  パッケージ側の自動有効化も同じイベントから非同期に着地するが、
  実行中の `enable()` は同じ Promise を返す仕様のため、二重に
  呼んでも競合しない。await の完了で遷移中表示が解け、表示は
  意図と最新のマイク状態から再計算されるので、次の
  `audioUpdate` を待たずに収束する。

残る制約は1つだけである。パッケージが実行時エラーで自己無効化
しても `audioUpdate` は発火しないため、その経路では表示（意図）が
実状態に遅れたままになる。影響は表示のみであり、次に意図を
切り替えれば実状態も追随する。この制約を受け入れる。

---

## 6. 判断が覆る条件（見直しトリガー）

以下のいずれかが真になったら、この ADR を再評価する。

1. **パッケージが変更イベントを持つようになった** → §5 の制約は
   解消されるので、イベント購読による同期へ移す
2. **UI Kit にノイズ除去の表示面ができた** → 独自ボタンをやめ、
   録画トグル側の扱いと合わせて移行する
3. **アセットの CDN 実行時ロードが要件に合わなくなった**
   （オフライン要件、ポリシー変更等）→ セルフホスト可否を含めて
   再検討する
4. **処理品質への不満が実測された** → デフォルト ON の是非を
   再検討する
